## 2. 研究方法与严格边界

### 2.1 两层分析法

#### A. 工具层
关注：
- IDE / Agent 体验
- 个人订阅 vs 团队 seat
- 团队治理
- 成员级使用可观测性
- AI 代码贡献归因能力

#### B. 模型层
关注：
- token 成本
- 速度
- 能力
- API 组织治理能力
- 适合放在哪一层任务路由中

### 2.2 证据优先级

- **A 级证据**：官方价格页 / 官方文档 / 官方 API 参考
- **B 级证据**：官方产品页 / 官方博客 / 官方案例
- **C 级证据**：第三方 benchmark / 测评 / 社区体验

硬结论（价格、额度、管理能力）优先采用 **A 级证据**。  
速度与 benchmark 允许引用 **C 级证据**，但会明确标注口径。

### 2.3 一个关键原则：不是所有方案都能“严谨算总成本”

本次将方案分为两类：

#### 透明可核算型
满足至少两项：
- seat 价格公开
- token 单价公开
- included usage 公开
- 可做统一 workload 归一化换算

代表：
- Cursor
- Claude / Claude Code
- OpenCode + API
- OpenAI / Anthropic / Google API 方案

#### 底价可核算型
存在以下问题之一：
- credits 到 token/模型消耗映射不透明
- request 制无法换算到统一 token 工作量
- 官方只给 plan，不给换算规则

代表：
- CodeBuddy
- Trae

> 因此：  
> 对 CodeBuddy / Trae 这类方案，本文只给：
> - seat/订阅底价
> - 含的额度
> - 可做的**假设性测算**
>  
> 不把假设值伪装成“精确账单”。

## 3. 统一成本基线：按“平均开发工作量”估算

### 3.1 采用的官方平均工作量口径

本次成本估算采用 Anthropic Claude Code 官方公开口径作为“平均开发工作量基线”：

- 平均约 **$6 / 开发者 / 天**
- 90% 用户低于 **$12 / 天**
- 常见月成本约 **$100–$200 / 人 / 月**

### 3.2 为了跨模型换算，增加透明假设

采用统一输入输出结构：

- **输入 : 输出 = 1 : 0.3**

### 3.3 推导出的平均月工作量

以 Sonnet 4.6 价格：
- 输入：$3 / 1M tokens
- 输出：$15 / 1M tokens

若平均日成本 = $6，则：

`3x + 15 * 0.3x = 6`

得到：
- 日均输入约 **0.8M**
- 日均输出约 **0.24M**

按 20 个活跃工作日 / 月：
- 月输入约 **16M**
- 月输出约 **4.8M**

### 3.4 本文成本口径

#### 平均工作量
- **16M input + 4.8M output / 月**

#### 重度工作量（P90 近似）
- **32M input + 9.6M output / 月**

> 注意：  
> 这只是统一预算估算口径，不代表任何单一平台的真实最终账单。

## 4. 工具层分析：优缺点、速度、能力、场景

> 说明：  
> 工具层的“速度”主要指 **交互体感 / 任务闭环速度 / 日常使用效率**，  
> 不是单纯模型 TTFT。

### 4.1 工具总表

### 4.2 分工具详细优缺点

#### Cursor

**成本**
- 个人：Hobby / Pro / Pro+ / Ultra
- 团队：Teams $40/人/月
- Enterprise：定制

**速度 / 体感**
- 日常 IDE 内编辑、多文件修改、补全、diff 体验强
- 对“边写边改”的效率非常高

**能力**
- 日常 feature / bugfix / refactor / review 最均衡
- 团队版治理不错
- 企业版支持 AI Code Tracking API

**适用场景**
- 个人默认主力
- 团队默认主工作台
- 中后台 / Web / SaaS / 通用研发

**优点**
- 最均衡
- 团队接受成本低
- 个人到团队可平滑升级

**缺点**
- 不是最便宜
- 如果最看重 commit 级 AI 占比，需要 Enterprise

#### Claude Code / Claude Team

**成本**
- 个人：Pro / Max 5x / Max 20x
- 团队：Standard / Premium seat
- Enterprise：定制

**速度 / 体感**
- 即时对话体感不如 Cursor 那么“轻”
- 但长任务闭环效率很高

**能力**
- 长链路 agentic coding 很强
- accepted lines、commit、PR、GitHub contribution metrics 完整
- 很适合效能分析

**适用场景**
- 复杂任务
- 平台与架构团队
- 想做 AI 研发效能量化的团队

**优点**
- 复杂任务成功率高
- 团队可观测性强
- 非常适合做 ROI 管理

**缺点**
- 成本偏高
- 工作方式更偏 agent，不是所有团队都能立刻适应

#### Trae

**成本**
- Free / Pro 低门槛

**速度 / 体感**
- 上手快，适合试试就用

**能力**
- 能满足试点和轻量开发
- 但公开团队能力证据偏弱

**适用场景**
- 个人尝鲜
- 小团队试点

**优点**
- 成本低
- 尝试门槛低

**缺点**
- 团队治理证据不足
- 不适合作为长期组织基线

#### CodeBuddy

**成本**
- 个人 Pro：$9.95/月，1000 credits/月
- 团队旗舰版：78 元/人/月，2000 credits/人/月
- 团队专享版：158 元/人/月，2000 credits/人/月

**速度 / 体感**
- 在国内场景更友好
- 支持 VS Code / JetBrains

**能力**
- 企业知识库
- SSO
- 模型配置
- 成员统计、研效看板
- 成员月度上限控制

**适用场景**
- 国内企业
- 强合规团队
- 知识库驱动开发

**优点**
- 组织管理强
- 国内采购和沟通成本低
- 团队 seat 成本不高

**缺点**
- credits -> token 映射不透明
- 公开资料里对代码归因精度不如 Cursor/Claude

#### OpenCode

**成本**
- 工具开源免费
- 企业版定制
- 模型成本完全外置

**速度 / 体感**
- 取决于你接的 provider 和内部网关
- 也可能因自建链路设计不同而明显变快或变慢

**能力**
- 75+ provider
- internal AI gateway
- centralized config / SSO / permissions

**适用场景**
- 平台团队
- 自控组织
- 自建 AI 网关团队

**优点**
- 自由度最高
- 最适合长期自控
- 本文最终推荐方案中，OpenCode 默认按**云模型路线**使用，不依赖本地模型

**缺点**
- 没有商业工具那样的开箱即用治理
- 需要平台能力

## 5. 模型层分析：优缺点、成本、速度、能力、场景

> 速度口径说明：  
> 主要引用公开第三方统一口径（如 Artificial Analysis），  
> 用于比较分层，不代表你们实际网络与 provider 的最终体感。

### 5.1 模型总表

| 模型 | 成本 | 速度 | 能力 | 适用场景 | 主要优点 | 主要缺点 |
|---|---|---|---|---|---|---|

## 7. 个人模式与团队模式：核心差异结论

### 7.1 个人模式适合什么

适合：
- 个人开发者
- 小团队试点
- 快速验证工作流

优点：
- 决策快
- 成本低
- 试错容易

缺点：
- 难做组织治理
- 难量化 ROI
- 难看成员级代码贡献

### 7.2 团队模式适合什么

适合：
- 已准备做规模化投入
- 需要预算、权限、知识库、审计
- 需要看 accepted lines / PR / commit / ROI

优点：
- 可治理
- 可分账
- 可量化

缺点：
- 采购和推广成本更高
- seat 成本上升

### 7.3 一句话

> **个人模式先证明“能提效”，团队模式再证明“值不值得持续投”。**

### 9.3 团队方案 T3：国内企业治理方案（CodeBuddy 终版口径）

**组合**
- 工具：CodeBuddy 旗舰版 / 专享版
- 额外透明模型路由：
  - GLM-5-Code：70%
  - MiniMax M2.5：30%

**关键假设（按你的要求）**
- **CodeBuddy 团队自带额度满足平均工作量的 60%**
- 剩余 **40%** 工作量用透明模型路由补足

**为什么这样算**
- CodeBuddy 自带 credits 与 token 的映射不透明
- 但 seat 价格和额度清楚
- 因此最科学的做法是：
  - 把 seat 当作“覆盖 60% 工作量的固定包”
  - 剩余 40% 用透明模型成本来补算

**透明外部路由的 100% 工作量成本**
- `0.7*GLM-5-Code + 0.3*MiniMax`
- `0.7*43.2 + 0.3*8.16`
- 约 **$32.69 / 人 / 月**

**因此 40% 外部补位成本**
- `32.69 * 40% = 13.08`
- 约 **$13.08 / 人 / 月**

**按汇率假设换算**
- 估算汇率：**1 USD ≈ 7.2 CNY**
- 外部补位约：
  - `13.08 * 7.2 ≈ 94.18 元 / 人 / 月`

#### 方案 T3a：旗舰版
- seat：**78 元 / 人 / 月**
- 外部透明补位：**约 94.18 元 / 人 / 月**
- **粗估总成本：约 172.18 元 / 人 / 月**
- 约 **$23.91 / 人 / 月**

#### 方案 T3b：专享版
- seat：**158 元 / 人 / 月**
- 外部透明补位：**约 94.18 元 / 人 / 月**
- **粗估总成本：约 252.18 元 / 人 / 月**
- 约 **$35.03 / 人 / 月**

**优势**
- 国内企业治理非常强
- 合规、知识库、成员上限控制适合组织落地
- seat 底价并不高

**缺点**
- 这是**基于 60% 覆盖假设**的估算
- 不是官方可审计账单公式
- 代码贡献归因公开精细度弱于 Cursor Enterprise / Claude

**结论**
- 在国内团队里，这是一套**很有竞争力**的团队治理方案
- 尤其适合：
  - 强合规
  - 知识库驱动
