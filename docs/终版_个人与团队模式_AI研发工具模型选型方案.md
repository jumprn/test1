## 2. 研究方法与严格边界

### 2.1 两层分析法

#### A. 工具层
关注：
- IDE / Agent 体验
- 个人订阅 vs 团队 seat
- 团队治理
- 成员级使用可观测性
- AI 代码贡献归因能力

#### B. 模型层
关注：
- token 成本
- 速度
- 能力
- API 组织治理能力
- 适合放在哪一层任务路由中

### 2.2 证据优先级

- **A 级证据**：官方价格页 / 官方文档 / 官方 API 参考
- **B 级证据**：官方产品页 / 官方博客 / 官方案例
- **C 级证据**：第三方 benchmark / 测评 / 社区体验

硬结论（价格、额度、管理能力）优先采用 **A 级证据**。  
速度与 benchmark 允许引用 **C 级证据**，但会明确标注口径。

### 2.3 一个关键原则：不是所有方案都能“严谨算总成本”

本次将方案分为两类：

#### 透明可核算型
满足至少两项：
- seat 价格公开
- token 单价公开
- included usage 公开
- 可做统一 workload 归一化换算

代表：
- Cursor
- Claude / Claude Code
- OpenCode + API
- OpenAI / Anthropic / Google API 方案

#### 底价可核算型
存在以下问题之一：
- credits 到 token/模型消耗映射不透明
- request 制无法换算到统一 token 工作量
- 官方只给 plan，不给换算规则

代表：
- CodeBuddy
- Trae

> 因此：  
> 对 CodeBuddy / Trae 这类方案，本文只给：
> - seat/订阅底价
> - 含的额度
> - 可做的**假设性测算**
>  
> 不把假设值伪装成“精确账单”。

## 3. 统一成本基线：按“平均开发工作量”估算

### 3.1 采用的官方平均工作量口径

本次成本估算采用 Anthropic Claude Code 官方公开口径作为“平均开发工作量基线”：

- 平均约 **$6 / 开发者 / 天**
- 90% 用户低于 **$12 / 天**
- 常见月成本约 **$100–$200 / 人 / 月**

### 3.2 为了跨模型换算，增加透明假设

采用统一输入输出结构：

- **输入 : 输出 = 1 : 0.3**

### 3.3 推导出的平均月工作量

以 Sonnet 4.6 价格：
- 输入：$3 / 1M tokens
- 输出：$15 / 1M tokens

若平均日成本 = $6，则：

`3x + 15 * 0.3x = 6`

得到：
- 日均输入约 **0.8M**
- 日均输出约 **0.24M**

按 20 个活跃工作日 / 月：
- 月输入约 **16M**
- 月输出约 **4.8M**

### 3.4 本文成本口径

#### 平均工作量
- **16M input + 4.8M output / 月**

#### 重度工作量（P90 近似）
- **32M input + 9.6M output / 月**

> 注意：  
> 这只是统一预算估算口径，不代表任何单一平台的真实最终账单。

## 4. 工具层分析：优缺点、速度、能力、场景

> 说明：  
> 工具层的“速度”主要指 **交互体感 / 任务闭环速度 / 日常使用效率**，  
> 不是单纯模型 TTFT。

### 4.1 工具总表

| 工具 | 成本特征 | 速度 / 体感 | 能力特征 | 适用场景 | 主要优点 | 主要缺点 |
|---|---|---|---|---|---|---|
| Cursor | 个人 $20 起；团队 $40/人/月；企业定制 | 高：IDE 内响应和多文件操作体验成熟 | IDE 协作最均衡；团队版可治理；企业版可做 AI 代码归因 | 日常业务研发、团队默认工作台 | 体验成熟、生态强、个人和团队都适用 | 企业级 AI 代码归因要上 Enterprise；总体成本不算最低 |
| Claude Code / Claude Team | 个人 $20 起；团队 seat 分层；重度更贵 | 中：即时聊天体感不如 IDE 快，但长任务闭环能力强 | 长链路 agentic coding、accepted lines/PR/commit 分析强 | 攻坚、平台团队、需要 ROI 的组织 | 复杂任务强、治理强、贡献指标强 | 成本高于试点工具；需要接受 agent 工作方式 |
| Trae | Free / Pro 低价 | 中高：上手快，试错快 | 适合快速试用和低成本起步 | 个人试点、小团队尝鲜 | 门槛低、便宜 | 团队 seat / 管理 / 归因公开证据不足 |
| CodeBuddy | 个人 $9.95/月；团队 78/158 元每人每月 | 国内网络与本地落地友好；体感偏好取决于模型/场景 | 国内团队治理、知识库、SSO、成员上限控制强 | 国内企业、合规组织、知识库驱动研发 | seat 便宜、组织落地强、管理清晰 | credits 映射不透明；精细代码归因公开证据弱 |
| OpenCode | 工具 OSS 免费；企业定制 | 取决于 provider / 本地模型 / AI gateway；可很快也可一般 | 最强的自控与定制能力 | 平台团队、隐私敏感、自建 AI 中台 | 开源、灵活、可接 75+ providers、本地模型友好 | 需要自建治理和观测；对普通团队不够省心 |

### 4.2 分工具详细优缺点

#### Cursor

**成本**
- 个人：Hobby / Pro / Pro+ / Ultra
- 团队：Teams $40/人/月
- Enterprise：定制

**速度 / 体感**
- 日常 IDE 内编辑、多文件修改、补全、diff 体验强
- 对“边写边改”的效率非常高

**能力**
- 日常 feature / bugfix / refactor / review 最均衡
- 团队版治理不错
- 企业版支持 AI Code Tracking API

**适用场景**
- 个人默认主力
- 团队默认主工作台
- 中后台 / Web / SaaS / 通用研发

**优点**
- 最均衡
- 团队接受成本低
- 个人到团队可平滑升级

**缺点**
- 不是最便宜
- 如果最看重 commit 级 AI 占比，需要 Enterprise

#### Claude Code / Claude Team

**成本**
- 个人：Pro / Max 5x / Max 20x
- 团队：Standard / Premium seat
- Enterprise：定制

**速度 / 体感**
- 即时对话体感不如 Cursor 那么“轻”
- 但长任务闭环效率很高

**能力**
- 长链路 agentic coding 很强
- accepted lines、commit、PR、GitHub contribution metrics 完整
- 很适合效能分析

**适用场景**
- 复杂任务
- 平台与架构团队
- 想做 AI 研发效能量化的团队

**优点**
- 复杂任务成功率高
- 团队可观测性强
- 非常适合做 ROI 管理

**缺点**
- 成本偏高
- 工作方式更偏 agent，不是所有团队都能立刻适应

#### Trae

**成本**
- Free / Pro 低门槛

**速度 / 体感**
- 上手快，适合试试就用

**能力**
- 能满足试点和轻量开发
- 但公开团队能力证据偏弱

**适用场景**
- 个人尝鲜
- 小团队试点

**优点**
- 成本低
- 尝试门槛低

**缺点**
- 团队治理证据不足
- 不适合作为长期组织基线

#### CodeBuddy

**成本**
- 个人 Pro：$9.95/月，1000 credits/月
- 团队旗舰版：78 元/人/月，2000 credits/人/月
- 团队专享版：158 元/人/月，2000 credits/人/月

**速度 / 体感**
- 在国内场景更友好
- 支持 VS Code / JetBrains

**能力**
- 企业知识库
- SSO
- 模型配置
- 成员统计、研效看板
- 成员月度上限控制

**适用场景**
- 国内企业
- 强合规团队
- 知识库驱动开发

**优点**
- 组织管理强
- 国内采购和沟通成本低
- 团队 seat 成本不高

**缺点**
- credits -> token 映射不透明
- 公开资料里对代码归因精度不如 Cursor/Claude

#### OpenCode

**成本**
- 工具开源免费
- 企业版定制
- 模型成本完全外置

**速度 / 体感**
- 取决于你接的 provider 和内部网关
- 用本地模型时可极快；也可能因自建链路变慢

**能力**
- 75+ provider
- 本地模型
- internal AI gateway
- centralized config / SSO / permissions

**适用场景**
- 平台团队
- 自控组织
- 本地模型 / 自建 AI 网关团队

**优点**
- 自由度最高
- 最适合长期自控

**缺点**
- 没有商业工具那样的开箱即用治理
- 需要平台能力

## 7. 个人模式与团队模式：核心差异结论

### 7.1 个人模式适合什么

适合：
- 个人开发者
- 小团队试点
- 快速验证工作流

优点：
- 决策快
- 成本低
- 试错容易

缺点：
- 难做组织治理
- 难量化 ROI
- 难看成员级代码贡献

### 7.2 团队模式适合什么

适合：
- 已准备做规模化投入
- 需要预算、权限、知识库、审计
- 需要看 accepted lines / PR / commit / ROI

优点：
- 可治理
- 可分账
- 可量化

缺点：
- 采购和推广成本更高
- seat 成本上升

### 7.3 一句话

> **个人模式先证明“能提效”，团队模式再证明“值不值得持续投”。**

## 8. 最终方案：个人模式组合搭配

### 8.1 个人方案 P1：主流均衡型

**组合**
- 工具：Cursor Pro
- 主力模型：Claude Sonnet 4.6
- 降本模型：Gemini 3.1 Flash-Lite
- 工程补位：GPT-5.3-Codex

**路由**
- Sonnet：70%
- Flash-Lite：20%
- GPT-5.3-Codex：10%

**优势**
- 工具和模型都成熟
- 日常开发体验最佳平衡

**缺点**
- 不是最低成本

**平均工作量月成本**
- 模型等效成本：`0.7*120 + 0.2*11.2 + 0.1*95.2`

- **粗估月总成本：约 $96 / 人 / 月**

- 成本透明

**实际预算建议**

### 8.4 个人方案 P4：开源自控型

- 云上模型：GLM-5-Code 30% + Gemini 3.1 Flash-Lite 20%

**缺点**

### 8.5 个人模式的补充说明：为什么 CodeBuddy / Trae 不放进透明预算主表

不是因为它们不能用，而是因为：

- **CodeBuddy**
  - 价格清楚
  - credits 清楚
  - 但 credits -> token/模型消耗映射不透明

- **Trae**
  - Free / Pro 和 fast requests 可见
  - 但 fast/slow requests 无法统一折算成透明 token 工作量

因此它们适合：
- 试用
- 低门槛起步
- 快速验证

但不适合放进“严谨月成本预算表”的主推荐方案。

**组合**

- 主力模型：Sonnet 4.6

**结论**

### 9.3 团队方案 T3：国内企业治理方案（CodeBuddy 终版口径）

**组合**
- 工具：CodeBuddy 旗舰版 / 专享版
- 额外透明模型路由：
  - GLM-5-Code：60%
  - MiniMax M2.5：20%
  - Gemini 3.1 Flash-Lite：20%

**关键假设（按你的要求）**
- **CodeBuddy 团队自带额度满足平均工作量的 60%**
- 剩余 **40%** 工作量用透明模型路由补足

**为什么这样算**
- CodeBuddy 自带 credits 与 token 的映射不透明
- 但 seat 价格和额度清楚
- 因此最科学的做法是：
  - 把 seat 当作“覆盖 60% 工作量的固定包”
  - 剩余 40% 用透明模型成本来补算

**透明外部路由的 100% 工作量成本**
- `0.6*GLM-5-Code + 0.2*MiniMax + 0.2*Flash-Lite`
- `0.6*43.2 + 0.2*8.16 + 0.2*11.2`
- 约 **$29.79 / 人 / 月**

**因此 40% 外部补位成本**
- `29.79 * 40% = 11.92`
- 约 **$11.92 / 人 / 月**

**按汇率假设换算**
- 估算汇率：**1 USD ≈ 7.2 CNY**
- 外部补位约：
  - `11.92 * 7.2 ≈ 85.82 元 / 人 / 月`

#### 方案 T3a：旗舰版
- seat：**78 元 / 人 / 月**
- 外部透明补位：**约 85.82 元 / 人 / 月**
- **粗估总成本：约 163.82 元 / 人 / 月**
- 约 **$22.75 / 人 / 月**

#### 方案 T3b：专享版
- seat：**158 元 / 人 / 月**
- 外部透明补位：**约 85.82 元 / 人 / 月**
- **粗估总成本：约 243.82 元 / 人 / 月**
- 约 **$33.86 / 人 / 月**

**优势**
- 国内企业治理非常强
- 合规、知识库、成员上限控制适合组织落地
- seat 底价并不高

**缺点**
- 这是**基于 60% 覆盖假设**的估算
- 不是官方可审计账单公式
- 代码贡献归因公开精细度弱于 Cursor Enterprise / Claude

**结论**
- 在国内团队里，这是一套**很有竞争力**的团队治理方案
- 尤其适合：
  - 强合规
  - 知识库驱动
  - 想低 seat 成本起步
